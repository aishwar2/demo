Understanding CI/CD

A clear breakdown of concepts, best practices, and architecture.

🔄

Continuous Integration (CI)

The practice of automating the integration of code changes from multiple contributors into a single repository.

  • Frequent Commits: Developers push small, frequent code increments.
  • Automated Builds: The CI runner creates a clean container for each run.
  • Automated Tests: Unit, integration, and security checks execute instantly.
  • Early Detection: Bugs are trapped within seconds of being written, avoiding "merge hell".
🚀

Continuous Delivery vs Deployment (CD)

Taking the tested code and getting it into the hands of users efficiently and reliably.

  • Continuous Delivery: Code is automatically built, tested, and packaged into a deployable release candidate. Deploying to production requires a manual 1-click approval.
  • Continuous Deployment: Every change that passes automated tests is released directly to production with zero human intervention (like this website!).
⚙️

The GitHub Actions Engine

How this site deploys automatically using GitHub's native automation server:

  • Workflow: Defined in YAML at .github/workflows/deploy.yml.
  • Events: Triggered on push: [main] or manually via workflow_dispatch.
  • Runners: Fresh Linux VM spun up in GitHub's cloud for every commit.
  • Artifacts & Pages: Assets are bundled and published to GitHub Pages CDN.
